# Project Humanity

Многоязычный сайт проекта «Человечество: реальная утопия». Включает информационные страницы, динамический каталог книг для чтения онлайн, регистрацию пользователей и раздел «Живая Книга» с откликами читателей.

## Возможности

- Интерфейс на русском и английском языках.
- Главная страница, разделы «О проекте» и «Принципы».
- Динамический каталог книг: список книг, чтение онлайн, ссылки на скачивание в разных форматах, обложки и описания.
- Регистрация, вход и профиль пользователя с загрузкой аватара.
- CAPTCHA и CSRF-защита форм.
- «Живая Книга»: публикация отклика на экземпляр книги, история откликов и интерактивный граф.
- Виджеты событий, новостей, таймлайна, социальных сетей и Telegram.
- Хранение контента в JSON-файлах или MySQL.

## Требования

- PHP с поддержкой возможностей, используемых проектом (в частности, `mbstring`, `PDO`, `fileinfo`, `GD` и `DOM`).
- Composer.
- MySQL — для режима хранения в базе данных и функций «Живой Книги».
- Веб-сервер, настроенный на каталог `public_html` как корень сайта.

## Установка

1. Установите зависимости:

   ```bash
   composer install
   ```

2. Подготовьте файл окружения.

   - Для локального окружения создайте `.env.local` в корне проекта.
   - Для production-среды загрузчик ожидает `config/.env.production`.

   Минимально необходима переменная `APP_DEBUG`. Пример локального файла для работы с MySQL:

   ```dotenv
   APP_DEBUG=true
   STORAGE_DRIVER=database
   DB_HOST=127.0.0.1
   DB_PORT=3306
   DB_NAME=project_humanity
   DB_USER=project_user
   DB_PASS=change_me
   SITE_VERSION=1.0
   ```

   Для режима JSON задайте `STORAGE_DRIVER=json`. Даже при JSON-хранилище переменная `APP_DEBUG` должна быть определена.

3. Проверьте `config/languages.json`, `config/books.php` и настройки базы в конфигурации. Файл `config/.settings.config` при отсутствии использует значения по умолчанию; в том числе настройку активности БД можно задать ключом `db_is_active=true` или `db_is_active=false`.

4. Убедитесь, что веб-сервер обслуживает каталог `public_html`. Каталоги с исходным кодом, конфигурацией и `storage` не должны быть доступны напрямую из интернета.

5. Предоставьте PHP-процессу права на запись в `storage/avatars` и `storage/books`. Для локального хранилища пользователей также требуется возможность создавать `storage/users.json`.

Не публикуйте файлы окружения и пароли от БД в репозитории.

## База данных и миграции

Миграции находятся в `migrations/`. Они запускаются в лексикографическом порядке имён файлов. Перед запуском убедитесь, что база и пользователь MySQL созданы и имеют необходимые права.

Проверка статуса подключения:

```bash
php bin/check_db_status.php
```

Применение миграций:

```bash
php bin/run_migrations.php
```

Скрипт миграций подключается к БД через контейнер приложения и создаёт таблицу `migrations` для учёта применённых файлов.

Для части сайта можно использовать JSON-хранилище. Однако репозиторий «Живой Книги» в текущей конфигурации создаётся на базе MySQL и требует настроенной БД и применённых миграций.

## Запуск локально

Для быстрой проверки через встроенный PHP-сервер:

```bash
php -S 127.0.0.1:8000 -t public_html
```

Откройте в браузере `http://127.0.0.1:8000`. Для полноценного запуска настройте веб-сервер так, чтобы корнем сайта был `public_html`.

## Маршруты

Все страницы обслуживаются через `public_html/index.php`; маршрут выбирается параметром `page`.

| URL-параметр | Страница |
| --- | --- |
| `?lang=ru` или `?lang=en` | Главная |
| `?page=about&lang=ru` | О проекте |
| `?page=principles&lang=ru` | Принципы |
| `?page=books&lang=ru` | Каталог книг (список) |
| `?page=books&book=<slug>&action=read&lang=ru` | Чтение книги |
| `?page=living_book&lang=ru` | «Живая Книга» |
| `?page=auth&action=login&lang=ru` | Вход |
| `?page=auth&action=register&lang=ru` | Регистрация |
| `?page=auth&action=profile&lang=ru` | Профиль |

Дополнительные действия «Живой Книги» включают создание отклика, получение данных графа (`action=graph-data`) и данных книги (`action=book-details&book_id=...`). Для создания отклика требуется авторизация.

Старый URL `?page=books&action=read` (без параметра `book`) не поддерживается и отдаёт 404.

## Контент и локализация

Переводы и данные сайта находятся в `locales/`, обычно в отдельных JSON-файлах для `ru` и `en`. Для событий, новостей и виджетов также используются файлы конфигурации вида `*.config.json`.

Доступные языки задаются через `config/languages.json`. Роутер использует только языки из этой конфигурации.

### Каталог книг

Книги хранятся как самодостаточные папки в `content/books/<slug>/`. Каждая книга обязана содержать манифест `book.json` и, опционально, файл оглавления `toc.md` и папку `chapters/` с markdown-главами.

Минимальная структура:

```text
content/books/<slug>/
  book.json
  toc.md                 (опционально)
  chapters/
    01-intro.md
    ...
```

Поля `book.json`:

| Поле | Обязательное | Назначение |
| --- | --- | --- |
| `id` | нет | Внутренний идентификатор; slug книги берётся из ключа в `config/books.php` |
| `title` | да | Название книги; поддерживает локализацию объектом `{"ru": "...", "en": "..."}` |
| `description` | нет | Описание для карточки в списке; поддерживает локализацию объектом |
| `author` | нет | Автор |
| `language` | нет | Код языка книги |
| `updated_at` | нет | Дата обновления в формате `YYYY-MM-DD` |
| `cover_url` | нет | Публичный URL обложки (относительный `/...` или абсолютный `http(s)://...`) |
| `chapters` | да | Массив глав: `id`, `file`, `title` |
| `formats` | нет | Дополнительные форматы скачивания (см. `config/books.php`) |

Пример `book.json`:

```json
{
  "id": "project-humanity",
  "title": "Проект Человечество: реальная утопия",
  "description": "Книга о переходе человечества к сознательному развитию.",
  "author": "Игорь Егоров",
  "language": "ru",
  "updated_at": "2026-11-07",
  "cover_url": "/images/covers/project-humanity.jpg",
  "chapters": [
    { "id": "preface", "file": "Preface.md", "title": "От автора. Предисловие" },
    { "id": "chapter-1", "file": "chapters/01-intro.md", "title": "Глава 1" }
  ]
}
```

`chapter.id` используется как стабильный HTML-якорь (`#preface`, `#chapter-1`). Если `id` отсутствует, невалиден или повторяется, генерируется fallback `chapter-N`. Ссылки в `toc.md` вида `[Название](path/to/file.md)` автоматически переписываются в якоря `#<chapter.id>`.

Глобальные настройки каталога (включение, порядок, папка, форматы скачивания, флаг `featured`) лежат в `config/books.php`:

```php
return [
    'project-humanity' => [
        'enabled'  => true,
        'order'    => 100,
        'featured' => true,
        'dir'      => 'project-humanity',
        'downloads' => [
            ['type' => 'fb2', 'label' => 'FB2', 'url' => '/books/project-humanity.fb2'],
            ['type' => 'pdf', 'label' => 'PDF', 'url' => '/books/project-humanity.pdf'],
        ],
    ],
];
```

Ключ массива — slug книги, по которому она вызывается в URL (`?page=books&book=<slug>&action=read`). Значение `dir` — папка внутри `content/books/`; если не задан, используется slug.

Файлы для скачивания (FB2, PDF и т.п.) размещаются в `public_html/books/` и выдаются веб-сервером напрямую.

## Добавление новой книги

1. Создайте папку книги:

   ```text
   content/books/<slug>/
   ```

2. Положите внутрь `book.json` с обязательными полями `title` и `chapters`, а также markdown-файлы глав (обычно в `chapters/`) и, при желании, `toc.md`.

3. Если нужны ссылки на скачивание — положите файлы в `public_html/books/` (например, `<slug>.fb2`, `<slug>.pdf`).

4. Добавьте запись в `config/books.php` с ключом `<slug>`, указав `enabled`, `order`, `dir` и `downloads`.

5. После `composer dump-autoload` (если добавлялись новые классы) книга появится на `?page=books` и станет доступна по `?page=books&book=<slug>&action=read`.

Обложка (`cover_url`) и описание (`description`) опциональны: если их нет, карточка и ридер отобразятся без них.

## Добавление новой вкладки

Страницы сайта регистрируются в `container.php`: там задаются маршруты и соответствующие контроллеры.

1. Создайте контроллер в `src/Http/Controllers/`. Обычно он наследуется от `AbstractController` и реализует метод `handle(string $page, string $lang): string`.
2. Подготовьте данные страницы в `src/View/`, создав класс, реализующий `TemplateDataInterface`, если странице нужны отдельные данные для шаблона.
3. Создайте шаблон в `includes/`. Контроллер может отрендерить его методом `$this->renderPage('имя_шаблона.php', $data, $page, $lang)`.
4. Зарегистрируйте контроллер в контейнере в `container.php` через `$container->singleton(...)`.
5. Добавьте маршрут в регистрацию роутера в `container.php`:

   ```php
   $router->addRoute('contacts', App\Http\Controllers\ContactsController::class);
   ```

   Первый аргумент — значение параметра `page` в URL. После регистрации страница будет доступна, например, по адресу `?page=contacts&lang=ru`.

6. Добавьте ссылку в меню в `includes/nav.php`, используя текущий язык и перевод названия вкладки.
7. Добавьте переводы для названия вкладки и её содержимого в `locales/` для каждого поддерживаемого языка. Для новой страницы с отдельным разделом контента можно создать, например, `locales/contacts/ru.json` и `locales/contacts/en.json`, а затем подключить для него репозиторий и сервис по аналогии с разделами `about` и `principles`.
8. При необходимости настройте боковые панели в конфигурации сайдбаров в `src/Infrastructure/ConfigLoader.php`, добавив настройки для нового ключа страницы.

## Добавление нового языка

1. Язык должен быть добавлен в `config/languages.json`, а переводы и локализуемые данные — в соответствующих каталогах `locales/`.

   Добавьте код и название языка в `config/languages.json`. Используйте код языка как ключ. Например, для французского:

   ```json
   {
     "ru": "Русский",
     "en": "English",
     "fr": "Français"
   }
   ```

   Сохраните существующие записи и добавьте новую, соблюдая синтаксис JSON.

2. Добавьте файлы локализации для нового языка. Как минимум подготовьте файлы, соответствующие текущей структуре проекта:

   ```text
   locales/
   ├── main/fr.json
   ├── about/fr.json
   ├── principles/fr.json
   ├── events/fr.json
   ├── events/fr.config.json
   ├── news/fr.json
   ├── news/fr.config.json
   ├── timeline/fr.json
   ├── timeline/fr.config.json
   ├── social/fr.json
   ├── social/fr.config.json
   ├── telegram/fr.json
   └── telegram/fr.config.json
   ```

   Структура JSON должна соответствовать файлам соседних языков в том же каталоге. Переведите все ключи интерфейса, которые использует сайт, включая подписи меню, кнопок и сообщения «Живой Книги».

3. Проверьте структуру контента: элементы массива и названия полей в JSON должны соответствовать существующим файлам `ru.json` или `en.json`. Для виджетов учитывайте также соответствующие `*.config.json`.

4. Обновите переключатель языка в `includes/layout.php`: сейчас ссылки RU и EN заданы явно. Добавьте ссылку для нового языка или измените переключатель, чтобы формировать ссылки на основе списка разрешённых языков.

5. Проверьте резервный язык в `src/Services/LanguageService.php`. Метод `validate()` сейчас возвращает `ru` для неизвестного кода, поэтому русский язык должен оставаться доступен либо логику fallback нужно изменить.

6. Проверьте сайт на новом языке: главную страницу, навигацию, страницы проекта, виджеты, авторизацию и «Живую Книгу». Убедитесь, что для нового языка существуют все необходимые файлы локализации и корректно отображаются тексты.

После добавления языка код принимается роутером из `config/languages.json`, но одних записей в этом файле недостаточно: нужно создать файлы переводов и добавить язык в переключатель `includes/layout.php`.

## Безопасность и эксплуатация

- В production установите `APP_DEBUG=false`.
- Используйте HTTPS и отдельного пользователя MySQL с минимально необходимыми правами.
- Загружаемые изображения проверяются по MIME-типу и сохраняются вне публичного каталога; выдача выполняется через отдельные скрипты.
- Не размещайте пользовательские загрузки и секреты в публично доступной директории.
- Ошибки приложения записываются в журнал сервера; подробности показывайте только в локальном режиме отладки.
- Slug книги валидируется по whitelist-регулярке `^[a-z0-9][a-z0-9_-]{0,63}$` (регистронезависимо) перед обращением к файловой системе.
- Пути к папке книги и к файлам глав резолвятся через `realpath()` с проверкой, что результат лежит внутри `content/books/`; попытки directory traversal (`../`, абсолютные пути) отклоняются.
- Публичные URL (обложки, форматы скачивания) нормализуются: допускаются только относительные `/...` и абсолютные `http(s)://...`; схемы `javascript:`, `data:` и protocol-relative `//` отклоняются.
- Markdown глав и оглавления конвертируется CommonMark с `html_input=strip` и `allow_unsafe_links=false`, поэтому сырой HTML и небезопасные ссылки из исходников вырезаются.
